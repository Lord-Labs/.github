# Governance

LORD Labs is currently maintained by [@Lord-shaban](https://github.com/Lord-shaban), the organization owner. Project-specific governance takes precedence within that project.

- Contributors propose focused changes through issues and pull requests. Maintainers decide scope, review evidence, and accept or decline contributions.
- Product roadmaps and existing dependency gates remain in each project's repository. The organization project board links to that work rather than replacing it.
- The organization owner manages repository access, security settings, releases, and changes to this governance document. Maintainer status and permissions require an explicit owner decision; contributing does not automatically grant access.
- Substantial architecture, license, privacy, or release-policy changes need an explicit discussion and maintainer decision before implementation. Keep the decision with the affected project.
- Repository licenses govern code. LORD Labs and product names, logos, and third-party artwork keep their separate terms.

Decisions should be explained in the relevant issue or pull request. Raise a disagreement respectfully with evidence; the maintainer makes the final project decision. Conduct concerns follow the [code of conduct](CODE_OF_CONDUCT.md), and vulnerabilities follow the [security policy](SECURITY.md).
