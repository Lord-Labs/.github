# Security policy

## Report privately

Use **Security → Report a vulnerability** in the affected repository:

- [ZipZap](https://github.com/Lord-Labs/ZipZap/security/advisories/new)
- [LOR.](https://github.com/Lord-Labs/lor/security/advisories/new)
- [NetScope](https://github.com/Lord-Labs/NetScope/security/advisories/new)
- [LORD Labs website](https://github.com/Lord-Labs/lordlabs.tech/security/advisories/new)
- [ZipZap website](https://github.com/Lord-Labs/zipzap-website/security/advisories/new)
- [Shared organization resources](https://github.com/Lord-Labs/.github/security/advisories/new)

Do not open a public issue containing exploit details or sensitive data. If the reporting form is unavailable, use a private contact method on [the maintainer's public profile](https://github.com/Lord-shaban); a public issue may request a private channel without including the vulnerability.

Include the affected repository and version/commit, a minimal reproduction, impact, and any proposed mitigation. Sanitize credentials, meeting recordings/transcripts, authenticated download URLs, household usage, and personal information. Do not test against other users or production data.

## Support and disclosure

The affected project's own security policy defines supported versions and takes precedence. Where it has no policy, only the current default branch and latest release, if any, are considered for fixes. Pre-release projects do not carry a production support guarantee.

Maintainers handle reports on a best-effort basis, coordinate remediation and disclosure, and credit reporters only with consent. There is no guaranteed response time or paid bounty program. Rotate exposed credentials immediately; removing a file does not invalidate a leaked secret or erase Git history.

## بالعربي

بلّغ بشكل خاص من **Security → Report a vulnerability** في المشروع المتأثر. اذكر الإصدار وخطوات إعادة المشكلة وتأثيرها، واحذف أي بيانات شخصية أو مفاتيح أو محتوى اجتماعات. ما تنشرش تفاصيل الاستغلال في Issue عامة.
